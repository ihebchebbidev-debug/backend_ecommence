# Backend rules
- Plan switches and overview readback run in one transaction without provider collection; repeated identical scheduled downgrades are no-ops, so retries cannot create misleading activation results or duplicate events.
- Team management uses authenticated owner/admin RPCs plus canManageTeam, allowlisted web roles/module actions and atomic session revocation; removed access keeps the member row for audit history, never grants platform roles or writes profiles.
- Mobile reference lookup shares live team-session validation and seller commerce permissions, matches exact shop-scoped identifiers and returns an allowlisted masked projection; it never prepares, pays or dispatches an order.
- Merchant payments share version-aware paymentCrypto across save, probe, checkout and callbacks.
- Store payment URLs derive only from the configured public storefront/API and activated shop domain; authenticated settings expose scoped addresses, and returns wait for provider readback because browser success/cancellation flags are not payment evidence.
- Carrier calls use `sendProviderRequest`; startup seeds missing rows only, preserving admin choices. Run `bun scripts/export-delivery-presets.ts` after admin preset edits to sync the server mirror, so deployments populate the catalog.
- Seller automation webhooks (Zapier/Make) use a trigger-filled `automation_events` outbox drained by a server worker with retries; URLs stay in a REST-denied table and only official hook hosts are accepted, so orders are never lost or posted to arbitrary addresses.
- Mobile order writes (edit, status, prepare) go through `mobileOrders.js`: one transaction, shop+permission check, `updated_at` version guard and a `mobile_idempotency` key per tap; the `order_events` trigger records every order change from any path, so history is never assembled client-side.
- Account deletion goes only through `account_delete` (rpc/account.js): password re-check, then one transaction closes owned shops, removes memberships, anonymizes login/profile and revokes sessions; platform billing records are retained for legal reasons.
- Payment callbacks settle only the order found by its saved payment reference, require provider order binding and matching currency/amount (shared minor-unit helper), and record a payment_mismatch seller notification instead of failing silently.
- Plan billing: commission adjustments and plan changes by admins go through super-admin RPCs in rpc/billing.js and are written to store_plan_events and admin_audit_logs, so every billing change is traceable. Exchange rates come from lib/exchangeRates.js (source='auto'); an active source='manual' row always wins.
- Storage reads honour bucket privacy: public URLs serve only public buckets; private objects and listings need the service role, a platform admin or the owner's `<user-id>/` prefix, so file paths alone never expose private uploads.
- REST writes without an explicit shop filter are limited to shops where the caller holds the table's write roles, and masked tables always fetch row ids, so id-only writes or narrow column selections cannot bypass role or commission rules.
- REST store policies declare a writePermission (store_role_permissions key) checked on every generic write, with unset keys falling back to lib/rolePermissionDefaults.js (mirror of web DEFAULT_ROLE_PERMISSIONS), so switching a feature off for a role closes indirect write routes.
- Order regression coverage lives in tests/orderFixes.e2e.mjs (`DATABASE_URL=<disposable db> npm run test:orders`): it boots the real server and stubs only payment providers, so order edit/delete/restore, earlier payment links and shop-currency rules fail loudly if broken.
- Checkout stock reservation follows status and trash together in record_commerce_order_event: releasing statuses or trashing an unshipped order give stock back once, restore/reopen take it again, and shipped/delivered orders never return stock on trash.
- Platform payment-method switches are `platform_settings` rows `payment_method_<code>_enabled` (missing = on) enforced through `_shared/platformPaymentMethods.js` in seller save, public options, order creation and payment start; callbacks stay untouched so payments already started still settle.
- Admin delivery "Active" sets `is_active` and `is_visible_to_stores` together; connected-provider reads, integration saves and dispatch require both, so a switched-off carrier vanishes from already-connected shops too.
- Shop configuration endpoints (payment/delivery setup, payment URLs) authorize through `_shared/storeAccess.js` canConfigureShop (active owner/admin membership plus the feature permission), never raw store_members role queries, so disabled members and switched-off permissions are refused.
- REST user-scope tables with `writeRoles: []` (admin roles, wallets, OTP logs) are read-only to their owners, and admin-scope writes need a super admin except limited-admin audit appends, so no session can grant itself roles or balances.
- Password changes over PUT /auth/v1/user require the current password unless the token is a fresh recovery session minted by /verify (amr recovery), so a stolen session cannot silently change the password.
- Traffic: web src/lib/visitTracker.ts reports path changes (admin/preview skipped) to `track_site_visit` into REST-denied `site_visits`; every API request is batched into REST-denied `api_request_logs` without query strings or bodies; IP from trusted proxy, country from edge headers or offline fast-geoip; only super admins read via `admin_traffic_*`/`admin_api_*`, because rows hold visitor IPs.
